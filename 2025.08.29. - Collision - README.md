    - 7.1 언리얼의 충돌 설정
        - 언리얼 엔진에서의 충돌체 제작 방법
        하나의 액터에는 세 가지의 충돌체가 모두 들어갈수도 있음에 유의.
        보통은 루트 컴포넌트로 설정되는 프리미티브 컴포넌트(캡슐, 박스, …)가 충돌체 역할.
        앞으로 나오는 “충돌체”라는 단어는 충돌을 담당하는 컴포넌트 혹은 그 영역을 의미함.
        **스태틱메시 컴포넌트**
        스태틱메시 애셋을 그대로 충돌체로 사용하는 방법.
        스태틱메시를 더블클릭하면 열리는 스태틱메시 에디터에서
        해당 충돌체 영역을 설정하고 확인할 수 있음.
        스태틱메시 애셋에 콜리전을 심으면 비주얼과 충돌이라는 두 가지 기능을 설정 가능.
        **기본 도형 컴포넌트(Primitive Component)**
        구체, 박스, 캡슐의 기본 도형을 충돌체로 지정하는 방법.
        스태틱 메시와 별도로 충돌체를 제작할 때 사용함.
        스켈레탈 메시와 함께 캡슐 컴포넌트가 사용되는 경우가 많음.
        **피직스 애셋**
        일반적으로 캐릭터의 이동은 캡슐 컴포넌트를 사용해서 처리함.
        하지만 특정 상황에서 캐릭터의 각 관절이 흐느적거리는 RagDoll 효과를 구현할때 사용함.
        각 부위에 기본 도형으로 충돌체를 설정하고 이를 연결해서 캐릭터의 충돌체를 설정함.
        피직스 애셋은 스켈레탈 메시에만 사용가능.
        
        - 충돌 설정의 세 가지 구분
        충돌체를 제작했다면, 관련된 설정들이 있음.
        스태틱메시 애셋에는 BlockAll이라는 기본 설정이 있어서 별도 설정 없이
        캐릭터 이동을 방해하는 레벨 컨텐츠를 제작할 수도 있음.
        플레이어가 레벨에 배치된 액터들과 올바르게 상호작용하려면 세부 설정이 필요.
        **Collision Enabled**(해당 충돌체가 어떤 반응할 수 있는가)
        **Object Type**(충돌체 분류)
        **Collision Responses**(다른 충돌체와 어떻게 반응할 것인가)
        이 세 가지를 콜리전 프리셋이라고 부름. 콜리전 프리셋과 콜리전 프로파일은 같은 뜻임.
        
        - 콜리전 프리셋 확인 방법
        Content Browser > BP_PlayerCharacter 더블클릭
        Outliner > BP_PlayerCharacter 클릭
        Details > SkeletalMeshComponent, CapsuleComponent > Collision > Collision Presets
        
        - Collision Enabled
        해당 충돌체가 어떤 반응할 수 있는가.
        액터마다 자신에게 적절한 충돌체 반응을 지정하는 것이 성능 상의 부하를 줄일 수 있음.
        **Query Only**
        두 충돌체가 서로 겹칠 때 신호만 보내는 반응할 수 있음.
        충돌체의 겹침을 감지하는 것을 언리얼 엔진에서 오버랩(Overlap)이라 부름.
        충돌체가 겹치면 해당 컴포넌트들의 BeginOverlap 델리게이트에 바인드된 함수가 호출됨.
        지정한 선 상에 물체가 충돌 되었는지 탐지하는 LineTrace나 Sweep도 Query에 속함.
        **Physics Only**
        두 충돌체가 서로 겹칠 때 물리적으로만 반응 할 수 있음.
        즉, 서로 밀어내거나 제한을 주거나(묶여있는 사슬 형태라서, …) 같은 반응만 할 수 있음.
        **Query and Physics**
        두 충돌체가 서로 겹칠 때, 위 두 반응을 모두 할 수 있음.
        이 설정을 사용하면 모든 기능을 사용할 수 있겠지만, 물리 엔진이 수행해야할 계산량 증가.
        
        - BP_PlayerCharacter의 Collision Enabled
        Collision Enable 부분을 보면 Query and Physics가 설정되어 있음.
        그리고 Generate Overlap Events에 체크 되어 있다는 것은
        다른 충돌체와 겹침이 발생하면 관련 델리게이트에 바인드된 함수 호출 될 수 있음을 의미
        
        - Object Type의 대분류
        여기서 나오는 “채널”이라는 용어는 분류(Category)를 의미함.
        **오브젝트 채널**
        충돌이 발생했을 때 특정 개체를 식별하기 위한 채널. 즉, 개체에 딱 붙어있는 충돌체 종류.
        WorldStatic / WorldDynamic / Pawn / PhyscisBody / …
        **트레이스 채널**
        특정 경로를 따라서 충돌을 감지하는 채널.
        Trace는 게임 엔진에서 자주 쓰는 용어. ex) LayTracing, …
        Visibility / Camera
        
        - Object Type의 소분류
        아래 충돌 채널 중 하나를 충돌체에 부여함.
        **WorldStatic**
        움직이지 않는 정적인 배경 액터에 부착된 충돌체(컴포넌트)에게 부여.
        주로 스태틱메시 컴포넌트를 가진 액터에게 부여됨.
        **WorldDynamic**
        움직이는 액터에게 사용하는 콜리전 채널.
        **Pawn**
        플레이어가 조종하는 폰 액터에 주로 사용.
        캐릭터의 충돌을 담당하는 캡슐 컴포넌트에게 부여됨.
        **PhysicsBody**
        물리 시뮬레이션으로 움직이는 컴포넌트에 부여됨.
        **Visibility**
        배경 액터가 시각적으로 보이는지 탐지하는데 사용. 탐지에서 폰은 제외.
        마우스로 물체를 선택하는 피킹 기능을 구현할 때도 사용됨.
        **Camera**
        카메라 설정을 위해 카메라와 목표물 간에 장애물이 있는지 탐지하는데 사용.
        DoCollisionTest 속성과 관련된 콜리전 채널.
        
        - Object Type 확인 중에 주의할 점
        Details > Collision Presets의 Pawn과 Object Type의 Pawn은 서로 다른 의미.
        Object Type을 봐야 정확한 콜리전 채널을 알 수 있음.
        Collision Presets는 Collision Enabled / Object Type / Collision Responses 모든 설정.
        뒤에서 배움. ex) Collision Presets에 Block All 선택하면 Object Type에 WorldStatic이 지정됨
        
        - Collision Responses
        해당 컴포넌트에 설정된 콜리전 채널이 상대방 컴포넌트의 콜리전 채널과
        어떻게 반응할지 지정하는 작업. 세 가지로 지정 가능.
        **무시(Ignore)**
        충돌이 있어도 아무 반응이 일어나지 않음. 뚫고 지나감.
        **겹침(Overlap)**
        무시와 동일하게 물체가 뚫고 지나갈 수 있지만, 이벤트 발생.
        **막힘(Block)**
        충돌체가 뚫고 지나가지 못하도록 막음.
        
        - BP_PlayerCharacter의 Collision Responses
        거의 모든 채널과의 반응이 Block임.
        
        - Collision Responses에 대한 고찰
        언리얼 엔진은 무시 반응을 최대화해서 성능을 고려함. 막힘 반응을 최소화함.
        A 컴포넌트의 콜리전 채널은 B 컴포넌트의 콜리전 채널에 대해 막힘 반응
        B 컴포넌트의 콜리전 채널은 A 컴포넌트의 콜리전 채널에 대해 겹침 반응이라면
        결국 둘은 막히지 않고 겹치게됨.
        
        - Overlap 이벤트와 Hit 이벤트
        Generates Overlap Events 속성이 체크되어 있고, 두 컴포넌트가 서로 겹침 반응이라면
        BeginOverlap 이벤트와 EndOverlap 이벤트가 발생함.
        Generates Hit Events 속성이 체크되어 있고, 두 컴포넌트가 서로 막힘 반응이라면
        Hit 이벤트가 발생함.

    - 7.2 충돌 감지와 디버그 드로잉
        - 콜리전 트레이싱 함수
        세 가지 카테고리로 원하는 함수 이름을 정할 수 있음. {***처리방법***}{***대상***}{***처리설정***}
        ***처리방법***
        LineTrace-/BoxTrace-/SphereTrace-/CapsuleTrace-/…
        Sweep-
        Overlap-
        ***대상***
        Test: 무언가 감지 되었는지를 테스트
        Single 또는 AnyTest: 감지된 단일 물체 정보를 반환.
        Multi: 감지된 모든 물체 정보를 배열로 반환.
        ***처리설정***
        ByChannel: 채널 정보를 사용해서 감지.
        ByObjectType: 물체에 지정된 오브젝트 타입(콜리전 채널) 정보를 사용해 감지.
        ByProfile: 프로파일(콜리전 프리셋) 정보를 사용해서 감지.
        
        - 캐릭터 공격의 충돌 감지 기획
        캐릭터의 위치에서 시선 방향으로 물체가 있는지 감지
        작은 구체를 제작하고 시선 방향으로 특정 거리까지 쓸기.
        여러 개체 감지.
        트레이스 채널을 사용해서 감지.
        {Sweep}{Multi}{ByChannel}

        - [실습] 공격 판정 구현
            
            액터의 충돌이 감지된 경우, 충돌된 액터와 관련된 정보를 얻기 위해 구조체를 넘김.
            또한 공격 명령을 내리는 자신은 이 탐색에 감지되지 않게끔 무시할 액터 목록에 추가.
            
            ```cpp
            // SXCharacterBase.h
            
            ...
            class SHOOTERX_API ASXCharacterBase : public ACharacter
            {
            	...
            
            public:
            	...
            
            protected:
            	...
            
            	UPROPERTY(EditAnywhere, BlueprintReadOnly)
            	float AttackMeleeRange = 50.f;
            
            	UPROPERTY(EditAnywhere, BlueprintReadOnly)
            	float AttackMeleeRadius = 20.f;
            
            #pragma endregion
            
            };
            
            ```
            
            ```cpp
            // SXCharacterBase.cpp
            
            ...
            #include "ShooterX.h"
            
            ...
            
            void ASXCharacterBase::HandleOnCheckHit()
            {
            	//UKismetSystemLibrary::PrintString(this, TEXT("HandleOnCheckHit()"));
            
            	TArray<FHitResult> HitResults;
            	FCollisionQueryParams Params(NAME_None, false, this);
            
            	bool bResult = GetWorld()->SweepMultiByChannel(
            		HitResults,
            		GetActorLocation(),
            		GetActorLocation() + AttackMeleeRange * GetActorForwardVector(),
            		FQuat::Identity,
            		ECC_ATTACK,
            		FCollisionShape::MakeSphere(AttackMeleeRadius),
            		Params
            	);
            
            	if (true == bResult)
            	{
            		if (HitResults.IsEmpty() == false)
            		{
            			for (FHitResult HitResult : HitResults)
            			{
            				if (IsValid(HitResult.GetActor()) == true)
            				{
            					UKismetSystemLibrary::PrintString(this, FString::Printf(TEXT("Hit Actor Name: %s"), *HitResult.GetActor()->GetName()));
            				}
            			}
            		}
            	}
            }
            
            ...
            ```

        트레이스 채널을 사용해서 물리적 충돌 여부를 가리는 함수 중 하나.
        물리는 월드의 기능이므로 GetWorld() 함수를 사용해서 로직을 짜야함.
        위 함수는 기본 도형을 인자로 받은 후 시작 지점에서 끝 지점까지 쓸면서
        해당 영역 내에 물리 판정이 일어났는지 조사함.
        ***HitResult***
        물리적 충돌이 탐지된 경우 관련된 정보를 담을 구조체
        ***Start***
        탐색을 시작할 위치
        ***End***
        탐색을 끝낼 위치
        ***Rot***
        탐색에 사용할 도형의 회전
        ***TraceChannel***
        물리 충돌 감지에 사용할 트레이스 채널 정보
        ***CollisionShape***
        탐색에 사용할 기본 도형 정보. 구체, 캡슐, 박스, …
        ***Params***
        탐색 방법에 대한 설정 값을 모아둔 구조체
        
        - 언리얼의 가비지 컬렉션과 FHitResult의 Actor 속성
        FHitResult의 Actor 속성 선언이 로우 포인터라면 
        해당 함수에서의 참조로 인해 제거 되어야 할 액터가 메모리에 그대로 남아있게 됨.
        이런 문제를 방지하기 위해 FHitResult는 참조로부터 자유롭게 포인터 정보를 
        전달해주는 TWeakObjectPtr 자료형으로 Actor 속성을 선언했음.
        TWeakObjectPtr로 지정된 액터에 접근하려면 IsValid() 함수를 사용해서
        사용하려는 액터가 유효한지 점검하고 사용해야함.
        위 예제에서 사용한 GetActor() 함수는 내부적으로 IsActorValid() 함수가 호출됨.

    - 7.3 TakeDamage()와 죽음 처리
        - TakeDamage() 함수
        감지된 액터에 데미지를 전달하기 위한 데미지 프레임워크가 제공됨.
        그 중 하나가 AActor::TakeDamage() 함수.
        TakeDamage() 함수는 총 네 개의 인자를 가지고 있음.
        DamageAmount
        전달할 데미지의 세기
        DamageEvent
        데미지의 종류
        EventInstigator
        공격 명령을 내린 컨트롤러. 
        DamageCauser
        데미지 전달을 위해 사용한 액터. 투사체나 무기 같은 액터.
            
            ```cpp
            /**
             * Apply damage to this actor.
             * @see https://www.unrealengine.com/blog/damage-in-ue4
             * @param DamageAmount		How much damage to apply
             * @param DamageEvent		  Data package that fully describes the damage received.
             * @param EventInstigator	The Controller responsible for the damage.
             * @param DamageCauser		The Actor that directly caused the damage (e.g. the projectile that exploded, the rock that landed on you)
             * @return				       	The amount of damage actually applied.
             */
            ENGINE_API virtual float TakeDamage(float DamageAmount, struct FDamageEvent const& DamageEvent, class AController* EventInstigator, AActor* DamageCauser);
            ```
